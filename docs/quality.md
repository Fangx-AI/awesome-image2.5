# 案例质量与验证

[首页](../README.md) · [贡献指南](../CONTRIBUTING.md)

## 什么可以放进精选展示

本项目完整案例必须有真实输出、完整提示词、生成来源和实际看图后的观察记录。编辑案例还需要输入图、修改目标与前后对比。外部来源作品允许只有提示词入口，但要明确缺失项，保留作者与模型证据。只写了提示词的条目可以进入实验区，不能作为模型能力的图片证据。

不把以下项目混为一个数量：
- 基础案例：不同的任务或场景。
- 任务侧重变体：在同一场景上强调细节、边缘、可读性等。
- 实际生成：有保存输出的生成记录。
- 精确模型实测：记录中能确认模型名的 API 调用。

## 每张图的检查

| 类型 | 首先检查 | 其次检查 |
| :--- | :--- | :--- |
| 中文海报 | 逐字准确、行序、标点 | 层级、对齐与留白 |
| 商品 | 轮廓、标签、材质 | 阴影、反射与背景 |
| 人物 / 宠物 | 身份特征、比例、姿态 | 毛发、手部、配饰边界 |
| UI | 标签、分组、主要动作 | 对齐、可读性和视觉一致性 |
| 信息图 | 事实与关系 | 箭头、标签、阅读顺序 |
| 编辑 | 修改目标是否完成 | 其余区域是否发生漂移 |

## 观察记录

用具体描述代替笼统的“完美”“顶级”：
- “两行标题均正确，瓶身小字出现额外字符。”
- “围巾加入成功，眼睛颜色和面部花纹保留；背景植物位置略变。”
- “主导航可以读出，三张卡片间距不完全一致。”

## 验证状态

- `prompt-only`：尚无对应真实输出。
- `host-model-unknown`：通过宿主工具生成，宿主未披露精确模型。
- `api-verified`：保存了指定模型的请求和输出记录。此标记不等于质量满分或结果可逐像素复现。

维护者或自动审核 Agent 必须查看实际输出并写下具体观察，才能将案例放进精选展示；无需人工逐条批准。程序通过关键词筛选不等于看图审核。详见[自动审核流程](automatic-updates.md)。来源作品的“官方示例、平台声明、作者声明”另见[证据说明](research.md#证据等级)，不能套用为本项目的 `api-verified`。
